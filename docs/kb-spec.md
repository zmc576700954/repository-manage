## 第一部分：核心理念

规范背后的五条设计哲学，比任何单条规则都重要。落地时不应丢弃。

### 1. 一切规则必须可被机器校验

每条规则都有**编号、级别、明确判据**，且能被自动检查工具验证。
"写完跑一次校验，合不合格当场有答案"——不依赖人肉评审，不依赖自觉。

推论：规则只定"能被正则级/静态分析判定"的东西。无法用机器安全判定的
（例如某些中文用词），宁可在校验器里沉默，并**把"为什么没查"写下来**，
避免后人误以为是许可或遗漏（盲区声明的由来，见附录 B）。

### 2. 分级管理：错误 vs 警告

- **错误（Error）**：结构完整性问题——断链、缺元数据、标题结构错误。
  必须修复，否则 CI 红、合入被拦。
- **警告（Warning）**：质量与新鲜度问题——编号不规范、复审过期、措辞不当。
  只提醒，不阻塞；提供 `--strict` 模式供严格要求时升级。

设计意图：让"必须改"和"建议改"分离，避免警告疲劳掩盖真正的错误。

### 3. 关联靠可达性，不靠元数据装饰

一篇文档必须能回答："读者从索引点进来，能不能找到它？"

- 知识库的关联体系 = **单一索引（README）+ 单向相对链接**。
- 不引入 wiki 双向链接、标签系统等额外机制。
- 核心判据：**从索引出发，沿站内链接必须能到达每一篇文档**。

### 4. 新鲜度是显式契约，不是隐含假设

每篇文档声明自己的生命周期状态和下次复审日期。校验器拿"今天"去比，
过期就亮警告——**同一份内容今天绿、三个月后可能黄，这是刻意的**。
知识会过期，规范把这个事实变成可见的、可追踪的信号。

> **rm 侧实现口径（D4）**：rm 校验器的 I3（180 天 mtime 陈旧）在条目声明了
> `下次 review` 时**让位**——新鲜度信号由 W6（复审过期）接管。
> 「最后更新」是人工登记的复核日期，刻意不取 mtime；Agent 不许代 bump
> （D7，批次 3 行为规范）。

### 5. 规范统一的是"规则集"，不是"长相"

命名风格（中文目录 vs 英文目录、是否加序号前缀）是**建议**；
真正卡死的是与风格无关的硬规则：可达性、链接合法性、标题结构、
元数据完整性。允许多个知识库风格不同，只要遵守同一套规则。

## 第二部分：结构规范

### 目录形状

```
<知识库根>/
└── <项目>/                        ← 一级目录 = 一个项目/主题库
    ├── README.md                  ← 唯一索引与入口（必须存在）
    ├── <分类目录>/
    │   ├── <文档A>.md
    │   └── <文档B>.md
    └── <分类目录>/
        └── <文档C>.md
```

**硬性要求（错误级）：**

| # | 规则 |
|---|---|
| S-结构-1 | 每个项目根必须有 `README.md`，它是唯一索引与入口 |
| S-结构-2 | 项目根只允许 `README.md`；其余文档必须落在分类目录下 |
| S-结构-3 | 路径（目录名+文件名）不得含空格、制表符及易出问题字符；建议只用中文、英文、数字、连字符 `-`、点 `.` |

**建议（警告级）：**

| # | 规则 |
|---|---|
| S-结构-4 | 分类目录与文档建议加 `NN-` 数字前缀（从 `01` 起，**不要求连续**）以控制排序 |

### 产物与源分离（如适用）

若知识库由导入流程生成：**校验的对象是产物，不是源**。
产物是读者真正读到的东西，且应提交进版本控制，CI 直接查它。
产物不要手改——改源，重新导入。

### 豁免

名字以 `_` 开头的目录（内部目录、测试夹具）默认不查；
显式点名时照查不误——点名是明确请求。

## 第三部分：元数据规范（frontmatter）

### 基本要求

- 文档**第一行**必须是 frontmatter 块（错误级）。
- 索引页 `README.md` 整组豁免——它是一张目录，不是一篇文档。
- 格式为**扁平标量**：每行一个 `键: 值`，恰好一个半角冒号加一个空格；
  不允许嵌套、列表、多行值。

### 四个必填键（占位项：键名可按团队语言习惯调整）

| 键 | 取值约束 | 含义 |
|---|---|---|
| `优先级` | 三值枚举（如 `🔴 P0` / `🟡 P1` / `🟢 P2`），全库含义一致 | **重要性分级**，用于"做决策时该不该读" |
| `状态` | 生命周期基准值之一，可跟 `（补充说明）` | 文档的可信度与维护状态 |
| `最后更新` | `YYYY-MM-DD` | 该条目在知识库中**登记/复核**的日期 |
| `下次 review` | `YYYY-MM-DD` 或 `按需` | 下一次该复核的日期 |

### 第 5 键：`文档代号`（批次 2 新增，Q12）

| 键 | 取值约束 | 含义 |
|---|---|---|
| `文档代号` | `NN-MM` 数字形态（如 `02-01`） | 文档的**稳定引用键**：目录序号-文件序号，可从路径机械派生 |

- 语义：依赖矩阵、跨文档引用、Agent 检索都以代号定位，路径/id 移动后代号不动。
- 规则 **M5（错误级，条件规则）**：键**存在**时取值必须匹配 `NN-MM`；
  **键缺失不报**——老库渐进补齐，强制齐全会把历史文档一次打成错误（附录 B）。
- rm 侧把它作为链接解析的最优先键（`resolve_target` 步骤 0），路径派生
  （目录首段数字-文件 stem 数字）兜底。

### 关键语义（最容易理解错的三点）

**1. 优先级 ≠ 阅读顺序。**
优先级回答"这件事做决策时必读吗"；阅读顺序是索引的事。
一篇进阶文档完全可以排在阅读路径靠后，同时是最高优先级。

**2. 状态是枚举，不是自由文本。**
基准值必须落在约定的生命周期集合内：
`草案` / `模板` / `稳定` / `需持续监控` / `过期` / `已归档`。
补充说明放括号里，基准值本身留在括号外。
rm 校验器对应规则 W7（键存在时校验，剥离括号注记后比对）。

**3. `最后更新` 是登记/复核日期，不是正文最后编辑的日期。**
取文件 mtime 会导致"同一份输入、不同机器、不同产物"。
因此内容更新后，需要**人工 bump 这个日期**——这是刻意的已知人工步骤，
忘了它就会得到一份"日期停在半年前"的文档。

### 复审过期（警告级）

`下次 review` 早于校验当天 → 报"已过复审期"警告。
拿校验当天比，所以警告会随时间自然出现——这正是新鲜度契约的落点。
kaiwu 对应规则 **M4**；rm 对应规则 **W6**（并使 I3 让位，见第一部分 §4）。

## 第四部分：标题规范

统计标题前，先剥掉代码围栏——代码块里的 `# 注释` 不算标题。

| # | 级 | 规则 |
|---|---|---|
| H-1 | 错误 | 每篇文档**恰好一个** H1 |
| H-2 | 错误 | 标题层级**不跳级**（H3 必须有 H2 父级；往回走不算跳级） |
| H-3 | 错误 | **相邻同级**标题之间必须有正文（下一段是子标题不算违规；只含代码块算有正文） |
| H-4 | 错误 | 标题内不得含 markdown 链接——链接放正文里 |
| H-5 | 警告 | 同级标题文字不得重复 |
| T-摘要 | 警告 | H1 之后应紧跟一句 `> ` 摘要，一句话说清这篇讲什么；**索引页豁免** |

已知盲区（校验器抓不到、规范要求自觉）：
`## A` → `### B`（无正文）→ `## C` 这种夹着子标题又缺正文的写法，
只比较相邻同级标题的校验器发现不了。规范应明说这一点。

## 第五部分：链接与关联规范

| # | 级 | 规则 |
|---|---|---|
| L-1 | 错误 | 站内链接必须以 `./` 或 `../` 开头的相对路径；裸文件名、根相对路径、绝对路径均非法 |
| L-1a | 错误 | 不使用 `[[wiki]]` 双向链接语法 |
| L-2 | 错误 | 站内 `.md` 链接的目标必须存在（**大小写敏感**、逐字相同），归一后不得越出项目根；非 `.md` 资源不查存在性 |
| L-3 | 错误 | **每篇文档必须能从项目 `README.md` 沿相对链接到达**——关联体系的核心判据 |
| L-4 | 警告 | 不得有孤儿文档（无入边且无出边；README 是图的根，不算孤儿） |
| L-5 | 错误 | `## 相关文档` 小节若存在：标题必须是**正好** `## 相关文档`、内容必须是 bullet list、每条指向存在的文档 |
| L-6 | 警告 | 链接文字须有描述性；禁「点击这里」「详见」等无信息指代 |

**批次 2 新增两条（解析健壮性与依赖矩阵）：**

| # | 级 | 规则 |
|---|---|---|
| L-7 | 警告 | 同项目内文件 stem 不得重复（rm 链接解析以 stem 为最后兜底，重名即二义；kaiwu 对应 L7 / rm 对应 W9） |
| L-8 | 警告 | README `## 依赖矩阵` 小节**若存在**：每行「依赖」列的代号必须 ⊆ 该文档 `## 相关文档` 小节的链接目标（依赖是相关文档的子集，两者是不同关系；D8-3；kaiwu L8 / rm W10） |
| L-9 | 警告 | 依赖/被依赖两列必须互惠：X 依赖 D ⟺ D 被依赖含 X（D8-3；kaiwu L9 / rm W11） |

L-8/L-9 是**条件规则**：`## 依赖矩阵` 小节不存在、或存在但没有合法表头
（须同时含「文档」「依赖」「被依赖」）→ 整体沉默。表格形态：
`| NN-MM | 代号、代号 | 代号 |`（依赖/被依赖单元格内代号以 `、` `,` `;` 分隔，
空单元格 = 无）。

要点：

- **写完文档一定要在 README 里加链接**——这是最容易忘的一步，忘了就 L3 断可达。
- L-5 标题写错**不会报错，而是整节不再被检查**——格式严格才能享受校验
  （L-8/L-9 沿用同一哲学）。
- 同一条坏链接可能同时命中多条规则（如 L-2 × L-5、L-6 × T-2），
  报多条是正常的，改一处一起消失。

## 第六部分：文本风格规范（警告级，只扫正文散文）

扫描前按顺序剥除：围栏代码块、行内代码、HTML 注释、链接目标（只留文字）、
裸 URL、`《…》` 书名片名。

| # | 规则 |
|---|---|
| T-1 | 禁全角感叹号；半角 `!` 只在紧跟中文时算 |
| T-2 | 禁「点击这里」「点击此处」等无信息指代 |
| T-3 | 禁「简单来说」「显然」「众所周知」等填充语 |

原则：风格规则只放警告级；误报率高的词（如中文的「请」「我们」）
**不查**，并在规范中写明不查的理由。

## 第七部分：工作流程

### 新建一篇文档（六步）

1. **建分类目录**（`NN-` 前缀是建议）。
2. **写 frontmatter**——第一行起，四个必填键齐全（规范 KB 推荐 + `文档代号`），枚举值合法。
3. **写正文**——一个 H1、层级不跳级、同级标题间有正文、H1 后紧跟摘要。
4. **写站内链接**——`./` 或 `../` 开头，目标必须存在。
5. **在项目 README 加一条链接**——⚠️ 最容易忘、且是错误级。
6. **跑校验**——确认无错误（按需处理警告）。

### 修改已有文档

- 第 1、2 步不用重做，但**第 5 步不能省**（新增/改名文档要同步索引）。
- 内容实质更新后，**人工 bump `最后更新` 日期**，并按需调整 `下次 review`。

### 日常维护

- 定期跑全库校验，处理「已过复审期」警告：复核内容 → bump 日期，或将状态改为 `过期`/`已归档`。
- 依赖外部易变信息（法规、价格）的文档，状态标 `需持续监控` 并给出明确的复审周期。

## 第八部分：校验器与退出语义（落地占位项）

kaiwu 用 `python scripts/check_kb.py`；rm 用 `cargo run --bin synapse -- validate <kb>`。两者只需满足：

- **支持全库查、按项目查**（按一级目录名过滤，可多个）。
- **退出码语义**：有错误 → 非零（CI 红）；只有警告 → 零；`--strict` 时警告也非零。
- **机器可读输出**（如 JSON）：按项目分组，每条发现带 `rule_id / level / path / message`；
  只给有发现的项目出条目，全库干净时输出空。
- 报告路径用**项目相对路径**（多个项目可能有同名文件，发现必须带所属项目）。

rm 的 JSON 形状与 kaiwu 不同（summary/issues vs 分组 findings），
适配器见 kaiwu `scripts/check_kb_synapse.py`（批次 0.5）。

## 附录 B：盲区声明汇编（D9）

> 每条机器不查的规则必须写明"为什么不查"，避免后人误以为是遗漏或许可。

1. **M5 键缺失不报**：强制 35+ 篇历史文档一次补齐会制造大规模错误墙。
   代号的价值在"写入后不随移动变"，渐进补齐即可；rm 编辑侧会在合适的时机
   （批次 3 Agent 规范）建议补键。
2. **L-8/L-9 小节不存在或表头不合法即沉默**：与 L-5 同哲学——格式严格才能
   享受校验。解析器对表格的假设（管道表、三列表头）写死在两个实现里，
   fixture 覆盖了"有节无表"的静默路径。
3. **M3 优先级枚举不进 rm**：`🔴 P0/🟡 P1/🟢 P2` 是团队占位项，通用 KB 的
   优先级词汇未约定，机器判了就是误报源。
4. **标题组（H1–H5/T4）与文本风格（T1–T3）不进 rm**：rm 的图谱/索引不消费
   标题层级；风格规则的误报治理成本高于收益（原文第六部分已声明）。
5. **rm 死规则清理（批次 2 执行）**：
   - `check_yaml_parse` 删除——空转规则（解析失败在 parser 层已捕获并降级），
     从未产出过 issue；
   - `check_unused_attachments` 删除——桩函数（返回空 vec），无判据无实现；
   - **E8 编号缺位声明**：rm 规则编号历史上跳过 E8（无规则占用过该编号），
     编号不回收，避免历史报告/ignore 配置里的 E8 引用产生歧义。
6. **新增规则的级别差异（\*）**：见附录 A 的级别差异标注——判据等价是
   fixture 比对的断言面；级别差异是产品语义（规范 KB 强、通用 KB 弱），
   双方各自合理。
7. **fixture 基线冻结纪律（沿用 kaiwu 口径）**：dev-kb CI 里的双黄金基线
   只能附理由更新；一次性消耗的基线漂移不可跨口径相减。

合计规则数：原 26 条（17 错误 + 9 警告）+ 批次 2 新增 4 条
（M5 错误级条件 + L7/L8/L9 警告级条件）= **30 条**。
