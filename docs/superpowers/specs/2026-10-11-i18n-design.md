# 国际化（中/英切换）设计方案

**代号**：i18n 中英切换
**日期**：2026-10-11
**状态**：待用户审阅
**关联文档**：[Synapse-KB 设计文档](./2026-10-09-synapse-kb-design.md)

---

## 1. 目标

当前 UI 字符串中英混杂（如 Sidebar.tsx 的 `title="在 KB 根目录创建新文档"` 与 "Add knowledge base" 同处一文件），给阅读和后续维护造成困扰。本设计引入完整 i18n 方案：

1. 所有 UI 文案（按钮、提示、占位符、Toast、空态文案）抽到翻译资源
2. 提供中/英运行时切换
3. 用户偏好持久化跨重启

**不在本次范围**：内部数据 ID、文件路径、KB 名称、Markdown 正文。这些是用户自有内容，不属于 UI 文案。

---

## 2. 关键决策

| 项 | 选择 | 理由 |
|---|---|---|
| i18n 库 | `react-i18next` | 行业标准；支持命名空间/插值/复数；bundle 增加 ~12KB gzip |
| 资源组织 | 按组件/视图分 namespace | 文件小、改动局部；与现有 `Sidebar.tsx` 等"一个组件一个文件"结构一致 |
| 切换器位置 | Settings 面板内字段 | 用户已选：发现性差换取主操作区干净 |
| 默认语言 | 浏览器 `navigator.language` 检测 | 用户已选：未设过偏好时尊重系统 |
| 偏好持久化 | Tauri `tauri-plugin-store` | 用户已选：跨 app 重启、不受浏览器缓存影响 |
| 翻译文件格式 | JSON | i18next 原生支持、与 TypeScript 解耦 |
| 语言自描述 | 中英两个固定值（"中文" / "English"） | 行业惯例；切换器在任何语言下都能看懂选项 |

│   ├── EntryDialog.tsx + .en.json / .zh.json

## 4. 启动流程

`src/i18n/index.ts` 暴露 `initI18n()`，**先 await 再 render**：

```ts
// main.tsx
import { initI18n } from './i18n';

await initI18n();                              // 异步但阻塞 root 渲染
ReactDOM.createRoot(...).render(<App />);
```

`initI18n` 内部：

1. 调用 `langStore.getLang()` 拿到已存语言；不存在则解析 `navigator.language`（`'zh*'` → `'zh'`，其他 → `'en'`）
2. `i18next.init({ resources, lng, fallbackLng: 'en', ns: [...], defaultNS: 'App', interpolation: { escapeValue: false } })`
3. 出错 → try/catch → 用硬编码 `'en'` 兜底，控制台 warn，app 不崩

**为什么不直接 `<Suspense>`**：i18next 的 `useSuspense` 会让所有 `useTranslation` 抛 Promise，整体都得包 Suspense，且 first paint 仍会闪；前置 await 在 main 入口更简单、保证 first paint 即正确语言。

## 5. 切换语言

`Settings.tsx` 顶部（`Knowledge Bases` 标题与 KB 列表之间）新增 **Language** 段：

```tsx
const { t, i18n } = useTranslation('Settings');

<div className="border-b border-gray-200 p-4">
  <div className="mb-2 text-sm font-medium text-gray-700">
    {t('language.label')}
  </div>
  <div className="flex gap-2">
    {(['zh', 'en'] as const).map((l) => (
      <button
        key={l}
        onClick={() => changeLanguage(l)}
        className={`rounded-md px-3 py-1.5 text-sm transition ${
          i18n.language === l
            ? 'bg-blue-500 text-white'
            : 'border border-gray-300 bg-white text-gray-700 hover:bg-gray-50'
        }`}
      >
        {t(`language.option.${l}`)}
      </button>
    ))}
  </div>
</div>
```

`changeLanguage(lang)`：先 `await i18n.changeLanguage(lang)` 触发重渲染，再 `await langStore.setLang(lang)` 持久化。两个操作互相独立：UI 立即响应，磁盘写入后台完成。

**资源**：

```jsonc
// Settings.zh.json
{
  "language": {
    "label": "语言",
    "option": { "zh": "中文", "en": "English" }
  }
}

// Settings.en.json
{
  "language": {
    "label": "Language",
    "option": { "zh": "中文", "en": "English" }
  }
}
```

注意 `option` 字段在两种语言下键值完全相同——语言名是惯例上的稳定项。

## 6. Tauri store 集成

**Rust 端**（`src-tauri/Cargo.toml`）：

```toml
tauri-plugin-store = "2.x"
```

**Rust 端**（`src-tauri/src/lib.rs` 在 `.plugin(...)` 链里追加）：

```rust
.plugin(tauri_plugin_store::Builder::new().build())
```

**前端**（`src/store/langStore.ts`）：

```ts
import { Store } from '@tauri-apps/plugin-store';

const STORE_FILE = 'preferences.json';
const LANG_KEY = 'language';

let store: Store | null = null;
async function getStore() {
  if (!store) store = await Store.load(STORE_FILE);
  return store;
}

export async function getLang(): Promise<string | null> {
  try {
    const s = await getStore();
    return (await s.get<string>(LANG_KEY)) ?? null;
  } catch {
    return null;
  }
}

export async function setLang(lang: string): Promise<void> {
  const s = await getStore();
  await s.set(LANG_KEY, lang);
  await s.save();
}
```

**为什么和 zustand 拆开**：zustand 同步、Tauri store 异步 + 磁盘；混在一起会让 zustand 首次值需要在 effect 里 set，复杂且难以推理。

## 7. 错误处理

| 场景 | 行为 |
|---|---|
| Tauri store 读失败 | `getLang()` 返回 `null` → fallback `navigator.language` 检测 |
| Tauri store 写失败 | `setLang` 抛错 → UI 立即切换不退回；用户重试或重启会重置。日志 warn |
| JSON key 缺失 | i18next 自动 fallback 到 `fallbackLng: 'en'` |
| init 整体异常 | `initI18n` 顶层 try/catch → 用 `'en'` 兜底 + `console.warn`，app 继续启动 |
| 未知 lang 值写 store | `Lang` 类型约束只在 TS 层；运行时写入非法值下次启动会 fallback |

**语言值约定**：写入 store 只用 `'zh'` 或 `'en'`（已并入 `Lang` 联合类型），不用 locale 变体；运行时检测也归一到这两值。

## 8. 不做的事（YAGNI）

- 不加 `<html lang="..."">` 同步更新：浏览器指示器由 React 内部处理，Tauri webview 不暴露
- 不做语言切换的快捷键
- 不做字符串提取 codegen（babel-plugin-i18next）；~150 个 key 人工维护可控
- 不做运行时翻译文件 lazy load；全部静态 import，bundle 增加 < 5KB
- 不引入 `vitest` / 测试框架；i18n 正确性靠手工验证（§9）

## 9. 验证（手工清单）

实现完成后依次跑：

1. **清缓存启动**：删 `~/Library/Application Support/com.*/preferences.json`（或对应平台的 appdata）→ app 检测浏览器语言 → 渲染对应文案
2. **首次切换**：Settings 切语言 → 整个 app（Sidebar / MapView / DetailPanel / EntryDialog）文案秒切
3. **持久化**：切换后完全退出 app → 重新启动 → 上次语言保持
4. **缺 key 容忍**：手工删 `Sidebar.zh.json` 的一个 key → 该位置显示 fallback 英文，浏览器控制台 warn 但不崩
5. **多语言环境**：把 macOS 系统语言切到英文、删偏好文件 → app 默认英文；切回中文系统 → 默认中文
6. **构建**：跑 `npm run tauri:build` 不报错；dev 模式 `npm run tauri:dev` 正常
